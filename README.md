# ResearchPilot 论文阅读助手

本地论文阅读与问答项目，由基础 Python Agent 练习扩展而来。支持导入文字型 PDF、选择一篇论文提问，并展示回答引用的原文、文件名和 PDF 页序。目标是让回答能回到原文核验，重点处理指标归属、证据上下文和调用失败等实际问题。

当前已完成单篇论文问答；可保存多篇文件，但每次问答只检索所选论文。两篇论文对比仍在计划中。本文更新于 2026 年 10 月 16 日。

## 已实现功能

- PDF 导入：按页提取文字，每片最多 800 字符、步长 680 字符；向量和原文元数据保存在 Chroma。
- 文件隔离与去重：以文件内容哈希识别论文，检索限定 paper_id；相同字节的文件重复上传不再次生成向量。
- 工具调用与循环：模型提出 search_paper 查询，Python 执行检索、回填证据，模型继续回答；最多 5 轮聊天模型调用，最后一轮禁止工具调用。
- 上下文补充：检索后补充同论文、同页相邻片段，按原文顺序去重合并，在模型生成答案前回填；网页展示相同证据。
- 引用检查：回答使用 [S1] 等编号，后端拒绝未知或缺失引用，兼容 [ S1 ] 这样的空白。
- 错误反馈：区分超时、连接失败、认证失败、权限拒绝、请求受限、上游参数错误和本地输入错误。
- 有限重试：复用 SDK 的 max_retries=1，符合条件时首次失败后最多再试一次；接口层不额外套重试循环。

引用编号存在不代表事实理解一定正确。无依据时要求模型说明依据不足，最终结果仍需对照原文核验。

## 环境与配置

本机已验证 Windows、PowerShell、Python 3.14.7；依赖固定在 requirements-paper.txt。其他环境需要单独验收。

在项目根目录执行；已有 .venv 时复用环境，跳过创建命令：

```powershell
cd C:\moxiu\ResearchPilot-paper-v0.2
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-paper.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
```

只在本机 .env 填写真实密钥；.env.example 保留占位值。修改配置后重启服务。

| 配置项 | 用途 |
| --- | --- |
| DASHSCOPE_API_KEY | 千问服务密钥 |
| DASHSCOPE_BASE_URL | 服务地址，须与密钥和服务匹配 |
| QWEN_MODEL | 聊天模型，当前默认 qwen-plus |
| QWEN_EMBEDDING_MODEL | 向量模型，当前默认 text-embedding-v3 |

聊天和 Embedding 分别需要可用的模型权限。

## 启动与使用

```powershell
.\.venv\Scripts\python.exe -m uvicorn paper_api:app --host 127.0.0.1 --port 8000
```

浏览器打开 http://127.0.0.1:8000/，终端保持运行；停止服务按 Ctrl+C。

2026 年 10 月 16 日本机按上述标准命令重新启动，`/health`、`/`、`/papers` 均返回 200，能够读取原有两篇文件。此次未调用聊天或 Embedding，不能据此判断外部模型连接可用。见[当天启动记录](验收数据/day7_startup.json)。

1. 上传一篇能复制文字的 PDF，等待导入完成。首次导入会调用 Embedding。
2. 选择论文，提出可核验的问题，例如“这篇论文解决什么问题？请给出原文出处”。
3. 展开引用，对照原 PDF 核验文件、页序、方法和数值；展开工具记录查看查询词及命中情况。
4. 测试论文没有依据的问题；切换文件后检查引用是否限定为所选论文。

导入限制：非空 PDF、不超过 20 MB、200 页、50 万提取字符和 1000 个片段。扫描件需另外 OCR。examples/demo.pdf 是虚构演示文本，不含真实科研结果。

### 本机临时网络方案

此前标准请求在本机受网络问题影响，真实千问验收使用 .venv/run_paper_api.py 的进程内临时方案：仅在服务进程内为千问域名指定地址并调整代理排除，HTTPS 域名与证书校验保留，没有改全局 DNS 或代理。

该脚本位于被忽略的 .venv 中，重建环境或复制项目后不会自动获得。其地址只代表此前验收时可用的临时路由，不是稳定部署方案。标准命令能启动网页，也不等于聊天与 Embedding 已连通，需分别验收。详情见[验证记录](docs/验证记录.md)。

## 主调用链

导入：

`paper_ui.html → POST /papers → PaperStore.ingest → parse_pdf → embed → Chroma`

问答：

`POST /ask → PaperAgent.ask → 模型提出查询 → PaperStore.search → expand_context → Agent 分配引用编号并回填 → 模型回答 → 引用检查 → 网页展示`

问答循环每轮先调用模型，模型可能提出一个或多个工具调用，也可能返回回答并结束。SDK 对一次具体请求的重试不增加 Agent 逻辑轮数。GET /papers 直接查库返回论文列表；提问框尚未实现“简单问题直接查库回答”的分流。

## 实际失败与改进

概括回答曾把 mAP 75.4% 归给 YOLOv8。人工核对原始 PDF 第 9 页及相邻片段，确认数值属于 Faster R-CNN。命中片段从词内开始、缺少方法名称；固定字符切片造成截断已确认，但不能认定它是误归属的唯一原因。

补充同页邻居后，该页固定片段由 205 扩为 885 字符，包含 Faster R-CNN [7] (mAP 75.4%)，数值未重复。真实千问针对“75.4% 对应哪种方法”的补问回答正确。补问与原概括问题分别记录，不将一次修正写成整体准确率提升。扩展外侧断词、页脚等问题仍在，见[引用改进设计](引用改进设计.md)。

## 已知限制与后续计划

- 单人本地学习应用，问答不保存跨问题历史，未部署公网或多用户服务。
- 跨论文对比、提问路由、笔记导出、长期记忆、重排和上下文压缩尚未实现。
- 表格、双栏、页脚和片段外侧边界可能影响提取；引用校验不验证事实语义。
- 最多 5 轮不是端到端超时；timeout=45.0 和 SDK 退避也不是问答总耗时上限。
- 429 尚未按服务商错误码细分暂时限流与额度耗尽；连接异常未自动定位具体网络原因。
- 已有记录多为检索一次后回答，尚未证明 Agent 循环优于固定 RAG；后续用同一论文与固定问题比较质量、调用次数、耗时和失败情况。
- 入库后不保存原 PDF，请保留原文件；更换 Embedding 模型会使用新集合，需要重新导入。
